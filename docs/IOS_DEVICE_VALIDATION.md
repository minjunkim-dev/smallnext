# iOS 핵심 흐름 실기기 검증

[#61](https://github.com/minjunkim-dev/smallnext/issues/61)의 실행 절차와 결과 기록 양식이다.
완료 조건과 판단은 Issue에 기록한다. 이 문서는 검증 통과를 뜻하지 않는다.
AI 품질과 출시 승인은 별도 검증이다.

## 설치와 실행

1. iPhone을 Mac에 연결하고 잠금을 해제한다. 기기의 신뢰 요청을 허용한다. Xcode가 요구하면 기기의 개발자 모드를 켠다.
2. `apps/ios/Smallnext.xcodeproj`를 Xcode에서 연다. `Smallnext` scheme과 연결한 iPhone을 선택한다. `Signing & Capabilities`에서 본인의 Team을 선택한다. 로컬 서명 설정은 커밋에서 제외한다.
3. `Edit Scheme > Run`에서 `Debug`를 선택한다. 로컬 실행 인자에 `-ios_core_flow YES`를 추가한다. `-development_ai_url`을 제거해 기존 Debug 고정 제안 공급자를 사용한다.
4. Run으로 설치하고 실행한다. 설치 실패 시 오류와 기기 iOS 버전을 기록한다. 시뮬레이터 성공으로 실기기 설치를 통과 처리하지 않는다.
5. 기록 양식에 앱 소스 SHA, 기기 모델, iOS 버전과 검증 날짜를 적는다. `git rev-parse HEAD`로 SHA를 확인한다.

실제 AI 연결이 필요한 추가 확인은 [Mac 개발 서버와 iOS HTTP 공급자](DEVELOPMENT.md#mac-개발-서버와-ios-http-공급자)를 따른다.
로컬 토큰은 결과 기록에 넣지 않는다. 이번 화면·모션 비교에는 고정 제안 공급자를 사용한다.
기존 앱을 삭제하면 로컬 진행 상태도 사라진다. 복구 검증에서는 앱을 삭제하지 않는다.

## 핵심 흐름

다음 세 목표를 각각 입력한다. 기존 고정 제안 공급자가 이 문구에 맞는 행동을 반환한다.

| 종류 | 목표 입력 |
| --- | --- |
| 업무 | 분기 업무 보고서 초안 쓰기 |
| 학습 | 통계 기초 단원 하나 학습하기 |
| 개인 | 개인 프로젝트로 베란다 화분 옮겨 심기 |

1. 목표를 입력한다. 완료 조건을 확인하고 확정한다. 현재 행동 하나가 보이는지 확인한다.
2. `더 작게`를 누른다. 새 행동과 분할 원본의 관계를 확인한다. 보조 메뉴의 `되돌리기`로 원본을 복원한다. 다시 `더 작게`를 누른다.
3. 행동 결과를 입력한다. `완료`를 누른다. 다음 행동과 앞선 결과를 확인한다. `목표 목록`에서 완료한 행동 수를 확인한다. 행동 완료를 목표 완료로 표시하지 않는지 확인한다.
4. 보조 메뉴의 `나중에`를 누른다. 자동으로 제시한 대체 행동도 `나중에`로 보류한다. `보류 중`에서 보류한 행동과 `재개`를 확인한다. `다른 행동 다시 찾기`를 확인한 뒤 원래 행동을 재개한다.
5. 목표 종류와 맞지 않는 문구, 읽기 방해, 버튼 조작 실패를 기록한다. 문제가 없다는 판단도 목표별로 기록한다.

## 강제 종료와 복구

1. 목표 입력 중 초안을 작성한다. 앱 전환 화면에서 Smallnext를 쓸어 올려 종료한다. 홈 화면에서 다시 연다. 목표 입력 초안을 확인한다.
2. 현재 행동에 입력 초안을 작성한다. 같은 방법으로 종료하고 다시 연다. 선택한 목표, 현재 행동과 입력 초안을 확인한다.
3. 현재 행동과 대체 행동을 차례로 보류한다. `보류 중`에서 종료하고 다시 연다. 보류 상태를 확인한다. 해당 행동을 재개한다.
4. 제안 대기 중 앱을 종료한다. 다시 연다. 중단 안내와 수동 재시도를 확인한다. 고정 공급자의 0.4초 대기를 놓쳤으면 미확인으로 기록한다. 재현을 위해 Debug 공급자의 반환 직전에 Xcode 중단점을 설정할 수 있다. 중단점에서 Stop 후 Run으로 확인한 결과는 앱 전환 화면에서 강제 종료한 결과와 구분한다.
5. 인터넷 연결을 끈 상태에서도 저장한 행동을 열고 입력·완료한다. 종료하고 다시 연다. 저장 결과를 확인한다. 고정 공급자가 반환한 다음 행동을 오프라인 AI 성공으로 기록하지 않는다.

## 접근성과 모션

1. 기기의 모션 감소를 OFF로 설정한다. `더 작게`와 `완료`를 각각 3회 확인한다. 이전 행동과 새 행동의 관계를 이해할 수 있는지 기록한다. 글을 읽거나 버튼을 누르는 데 방해가 있는지 기록한다.
2. 모션 감소를 ON으로 설정한다. 같은 흐름을 확인한다. 갈라지는 이동 없이 문구로 행동 변화를 이해할 수 있는지 확인한다.
3. VoiceOver를 켠다. 목표 입력, 완료 조건 확정, 행동 결과 입력, `더 작게`, `완료`, `나중에`, 재개를 수행한다. 읽기 순서, 버튼 이름, 상태 변경 안내와 새 카드 접근을 확인한다. 장식용 분할 조각을 별도 요소로 읽지 않는지 확인한다.
4. Dynamic Type을 접근성 최대 크기로 설정한다. 목표 입력·현재 행동·목표 보기·목표 목록을 확인한다. 문구, 입력란과 버튼에 잘림이나 겹침이 있는지 확인한다. 스크롤로 모든 조작에 접근할 수 있는지 확인한다.
5. 로컬 `-ios_core_flow YES` 인자를 제거하고 Xcode에서 다시 실행한다. 기존 안내 화면을 확인한다. ON 인자를 복원해 기존 진행 상태를 다시 확인한다.

## 모션 값 기록과 판단

현재 코드 위치는 `apps/ios/Sources/CoreFlowView.swift`이다.
아래 값은 실기기 비교의 시작값이다. 최종 승인 값이 아니다.

| 항목 | 시작값 | 최종 값 | 판단 근거 |
| --- | --- | --- | --- |
| 분할 시간 `Motion.split` | 0.34초 | 미확인 | 실기기 확인 필요 |
| 다음 카드 투명도 전환 `Motion.nextCard` | 0.18초 | 미확인 | 실기기 확인 필요 |
| 위 조각 이동 `(x, y)` | `(-6, -9)` pt | 미확인 | 실기기 확인 필요 |
| 아래 조각 이동 `(x, y)` | `(12, 24)` pt | 미확인 | 실기기 확인 필요 |

1. 시작값에서 문제를 기록한다. 문제가 없으면 값을 유지한 이유를 기록한다.
2. 문제가 있으면 해당 값 하나를 수정한다. 같은 기기와 목표에서 다시 확인한다. 기존 값과 수정 값을 비교한다.
3. 채택한 값과 읽기·조작·행동 변화 이해에 대한 근거를 Issue에 기록한다. 코드와 값이 일치하는지 확인한다.
4. 모션 감소, VoiceOver와 최대 Dynamic Type을 수정한 값으로 다시 확인한다.
5. `ios_core_flow` 활성화 판단을 Issue에 기록한다. 미확인 항목이 있으면 기본 OFF를 유지한다. 사용자용 ON 변경은 [피처 플래그 절차](WORKFLOW.md#피처-플래그)를 따른다. 이 검증만으로 Release 공급자나 출시 품질을 승인하지 않는다.
