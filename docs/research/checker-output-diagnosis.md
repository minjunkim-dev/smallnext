# 출력 오류와 검사 지연 재검증 #96

[#96](https://github.com/minjunkim-dev/smallnext/issues/96)의 후속 진단이다.
2026-10-10에 [#97 하네스](oauth-quality-evaluation.md)로 실제 Claude Code 구독 OAuth 호출을 수행했다.
`claude-haiku-5-5`, `xhigh`, 기존 `claude.ai` 구독 로그인을 유지했다.
API 키를 사용하거나 토큰을 추출하지 않았다. 서비스 공급자·다섯 검사 기준·피처 플래그 기본 OFF는 유지했다.

## 재현과 원인

과거 품질 45/47의 중단 두 건은 [기존 receipt](fixtures/oauth-quality-results.json)에 그대로 남는다.
과거 Rust 수용14/14·상태 참조13/14도 그대로 남는다.
당시 스트림 원문이 없으므로 당시 잘못된 필드와 값을 소급하여 확정하지 않는다.
같은 사례와 원래 프롬프트로 스키마 오류 후의 추가 요청 경로를 새로 재현했다.

- `generate-next` 세 번 중 두 번에서 추가 요청이 발생했다. 한 재현의 오류 필드는 `remaining_work`였다.
- `replacement-empty-invalid`를 원래 검사 프롬프트로 12회 실행했다. 10회는 참조와 일치했다. 두 번은 `reason`의 스키마 오류였다.
- 두 사례 모두 `StructuredOutput`의 스키마 위반 → `tool_result.is_error=true` → 새 message ID의 두 번째 응답 순서였다.
- `max_tokens=0`, 제공자 retry=0이었다. 같은 응답의 중복 집계도 아니었다.

Claude CLI는 스키마 불일치에서 재요청할 수 있다. [공식 구조화 출력 문서](https://code.claude.com/docs/en/agent-sdk/structured-outputs)가 이 동작을 설명한다.
기존 하네스는 두 번째 응답을 관측한 뒤 중단했다. 원인을 기록할 메타데이터가 없었다.
안전한 이벤트·유효성·오류 필드명·구간 시간 계측을 추가했다. 원문 추론과 자격 증명은 저장하지 않는다.
두 번째 응답을 허용하거나 잘못된 출력을 수용하지 않는다.

공통 계약에는 기존 JSON 타입을 명시했다.
남은 범위와 완료 ID는 한 항목이어도 문자열 배열이다. 완료 플래그는 boolean false이고 시간은 숫자다.
복사·보존·상태 선택·다섯 기준의 의미는 변경하지 않았다.

## 검사 지연 분리

기존 후보 두 개를 각각 두 번 검사한 초기 계측은 4/4 수용이었다.

추론 구간은 34.597~35.712초였고 형식 도구 출력 구간은 2.564~3.606초였다.
이 계측 중 일부는 별도 원인 점검과 겹쳤다. 개선 대조의 기준값으로 사용하지 않는다.
자동 수정 요청과 정상 검사의 긴 추론을 별개의 문제로 구분한다.
이 증거로 모델 자체의 한계나 추론 내부의 반복 원인을 확정하지 않는다.

## 출력 방식 교차 측정

공통 계약에 JSON 타입을 명시한 뒤 출력 방식 하나를 바꿨다.

새 방식은 한 번의 JSON 응답을 받은 뒤 동일한 로컬 스키마를 검증한다.
새 방식에는 같은 역할 지시와 스키마를 출력 지시로 전달한다.
잘못된 JSON·중복 키·잘못된 타입·누락·추가 필드를 실패로 남긴다. 자동 수정하지 않는다.
