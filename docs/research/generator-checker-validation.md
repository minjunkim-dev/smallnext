## 구현 결함과 수정

기존 구조 검사는 goal_preparation에서 일반 action을 허용했습니다.
새 회귀 테스트가 기존 코드에서 실패했습니다. goal_preparation → action이 잘못 수용됨을 확인했습니다.
요청별 허용 status를 생성 schema와 구조 검사에서 함께 사용하도록 수정했습니다.
모든 요청에서 모든 status를 생성하도록 허용하던 schema를 좁혔습니다.

| 요청 종류 | 허용 status |
| --- | --- |
| goal_preparation | goal_summary, need_info |
| first_action, next_action, smaller | action, need_info, minimum |
| replacement | action, need_info, minimum, no_action |
| 종류를 생략한 기존 입력 | action, need_info, minimum |

부적합 status를 반환한 제공사 응답은 구조 검사에서 계속 차단합니다.
schema가 의미 품질을 보장한다고 가정하지 않습니다.
개발 CLI와 사용자용 API는 같은 생성·검사 프롬프트를 사용합니다.
사용자용 API의 중복 추가 정책을 공통 프롬프트로 옮겼습니다.
알려진 제목 복사와 알 수 없는 과거 사실의 근거 확보를 구분합니다. 제목 작성 자체가 목표인 경우는 허용합니다.
모델·추론 강도·timeout·예산·자동 재시도·피처 플래그를 변경하지 않았습니다.

## 계약 회귀 검사

- 요청 종류·status 30조합에서 구조 검사와 생성 schema가 일치합니다.
- 잘못된 요청 종류·빈 입력·시간·입력 크기를 차단합니다.
- 잘못된 status에서 의미 검사를 호출하지 않습니다. 기존 행동을 보존합니다.
- 남은 범위·완료 ID·미완료 상태·빈 필드·예상 시간의 위반을 차단합니다.
- 검사 응답의 누락 기준·빈 근거·잘못된 값·추가 필드를 차단합니다. 거절·불확실을 수용으로 바꾸지 않습니다.

Rust 일반 테스트 29개를 통과했습니다. 기본 실행은 DB 테스트 11개를 생략합니다.
별도의 격리 PostgreSQL 18에서 DB 마이그레이션 1개와 사용자용 API HTTP 통합 10개를 모두 실행하고 통과했습니다.
모의 제공사의 요청에서 공통 프롬프트·요청별 schema·원본/후보 전달·호출 수를 확인했습니다.
Firebase와 제공사 응답은 합성입니다. 실제 API 인증·청구 검증이 아닙니다.
iOS 테스트 87개와 Python 테스트 107개를 통과했습니다.
repository/workflow/clippy/OpenAPI/diff 검사도 통과했습니다.
iOS ProgressFlowTests의 기존 actor 경고 3개는 수정하지 않았습니다.

## 평가를 실행 전에 고정

[평가 입력](fixtures/generation-check-contracts.json)을 실제 호출 전에 고정했습니다.
새 검사 후보는 책장 목표 확인·책 수량 축소·번역 다음 행동·과거 날짜 근거·보류 대체·카드 한 단어의 정상/실패 쌍 12개입니다.
생성 입력은 다섯 요청 종류와 누락 근거·명시적 반복 실패·정상 중첩 분할을 포함한 8개입니다.
기대 판정·사례 ID·참조 이유는 모델에 전달하지 않았습니다.
새 후보의 원문은 이번 프롬프트 보정에 사용하지 않았습니다. 결함 유형 자체는 기존 지침에 알려져 있습니다.
평가 결과를 본 뒤 이 입력에서 통과하도록 프롬프트를 다시 보정하지 않았습니다.
참조는 AI가 작성한 합성 기준입니다. 사람의 전수 품질 승인이나 일반화 성능을 뜻하지 않습니다.

어댑터는 준비한 합성 입력·프롬프트·schema만 허용했습니다. 완료 응답의 실제 모델을 확인했습니다.

새 키·OAuth 토큰 추출·일반 API 호출은 없습니다. 영구 개발 공급자는 기존 Codex CLI를 유지합니다.

## 생성기 단독 검토와 연결 결과

생성 입력 8개는 각각 1회 실행했습니다. 최종 구조화 응답 8개는 구조 검사를 통과했습니다.
원문을 참조 기준과 별도로 비교했습니다. 7개는 일치했고 1개는 보류 행동을 표현만 바꿔 재제안했습니다.
실제 Rust 연결 경로도 7개를 수용하고 이 1개를 의미 검사에서 거절했습니다.
검사에서 차단했다고 유용한 답을 제공한 성공으로 계산하지 않습니다.

| 생성 입력 | 원문 검토 | 연결 결과 |
| --- | --- | --- |
| 책장 목표 확인 | 관찰 가능한 최종 목표 초안 | goal_summary 수용 |
| 책 여섯 권 축소 | 한 권으로 실제 작업 감소 | action 수용 |
| 다음 번역 문장 | 완료한 첫 문장을 반복하지 않음 | action 수용 |
| 과거 날짜의 자료 출처 | action에 실제 질문 하나 | need_info 수용 |
| 준비된 대안 없는 펜 대체 | 보류된 빨간 펜 반납을 표현만 변경 | 거절, 미통과 |
| 카드 이름 한 단어 | 주어진 이름 한 단어만 작성 | action 수용 |
| 명시적 반복 시작 실패 | 첫 실제 막힘 하나를 직접 질문 | need_info 수용 |
| 정상 중첩 분할 | 반복 실패를 추정하지 않고 세 권을 한 권으로 줄임 | action 수용 |

대체 실패 후보는 '펜꽂이에 넣기'와 '반납'을 서로 다른 준비된 행동으로 해석했습니다.
목표에서 반납 장소를 각 펜꽂이로 정했으므로 같은 보류 행동입니다. 검사기는 기준 2·4 위반으로 거절했습니다.
생성 결과를 자동 수정·재생성하지 않았습니다. 실패 연결 결과는 이전 상태를 보존했습니다.
7/8은 이 합성 입력의 요청 결과입니다. 유용한 행동 7개나 전체 품질 통과율이 아닙니다.
연결 실행 시간 중앙값은 23.3395초, 최대는 40.953초입니다.
생성·검사 출력 합계는 45,234토큰, 단일 최대는 7,142토큰입니다. 생성만의 출력 합계는 9,989토큰입니다.

## 시뮬레이터와 한계

별도 QA 시뮬레이터의 기존 합성 업무 목표에서 새 서버를 실행했습니다.
메뉴를 닫는 과정에서 나중에를 잘못 눌러 대체 요청이 시작됐습니다. 취소 전에 요청이 완료됐습니다.
이 요청은 no_action을 생성했고 검사 수용 후 보류 상태를 유지했습니다. 원래 2분 행동을 재개했습니다.
그 뒤 더 작게를 한 번 요청했습니다. action을 생성했지만 생성에 116.181초가 걸렸습니다.
의미 검사는 전체 120초 제한으로 취소됐습니다. 앱은 시간 초과를 표시했고 기존 행동을 유지했습니다.
후보는 빈 둘째 줄을 만드는 준비 행동입니다. 의미 검사 결과를 받지 못했으므로 유용한 축소 수용으로 기록하지 않습니다.
DB에서 현재 행동 4·완료 행동 1의 결과·보류 행동 5를 확인했습니다. 새 요청 18은 timed_out 실패입니다.
화면 흐름의 시간 내 성공은 미통과입니다. 실제 외부 보고서 작성이나 실기기 사용 증거가 아닙니다.
임시 QA 서버와 격리 DB 컨테이너는 검증 후 중지했습니다. 피처 플래그 기본값은 OFF입니다.

평가 하네스의 CLI 실행은 검사 33개와 생성·검사 연결 16개로 49개입니다.
화면 검증은 별도 4개를 시작했습니다. 3개는 완료했고 1개는 취소됐습니다.
완료 CLI 응답의 num_turns는 2 또는 3입니다. 내부 turn을 제공사 HTTP 호출 수와 동일하게 계산하지 않습니다.
하네스와 Rust는 실패 뒤 재시도하지 않았습니다. Claude Code 내부 호출·출력 정리·재시도의 분해는 확인하지 않았습니다.
CLI에서 API 출력 8,192·HTTP 30초 제한을 강제하지 않았습니다. CLI 시간·토큰은 API 비용·지연을 뜻하지 않습니다.
합성 원문·참조·프롬프트/schema·응답·실패는 로컬 validation92와 validation92-ui에 보존했습니다.
원문 보관 기한은 2026-11-08입니다. 자동 삭제는 없습니다. 운영 원문 로그를 추가하지 않았습니다.

계약 구현의 결함을 수정하고 현재 회귀 경로를 검증했습니다.
Haiku 5.5/xhigh의 생성 의미 실패와 실제 화면 시간 초과는 남았습니다. 모델의 출시 적합성을 승인하지 않습니다.
