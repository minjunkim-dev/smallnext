# 결정 출력 품질·지연 검증 #96

Claude Code 구독 OAuth, `claude-haiku-5-5`, `xhigh` 요청을 유지한다.
다섯 의미 기준과 합성 참조를 유지한다. 제품 응답 시간 목표는 확정하지 않는다.
과거 결과는 덮어쓰지 않는다.

## 변경 범위

생성 모델은 상태·행동·완료 조건·이유·예상 시간만 출력한다.
런타임은 원래 남은 작업과 완료 ID를 복사한다. 두 완료 플래그는 false다.
모델이 보존 필드를 출력하면 추가 필드 오류로 차단한다.
원래 상태를 모델이 다시 쓰는 경로를 제거한다. Rust의 최종 보존 검사는 유지한다.

검사 모델은 판정·기준 번호·인용과 설명을 출력한다.
런타임은 같은 설명을 API의 이유 필드에 복사한다.
모델이 이유 필드를 따로 출력하면 추가 필드 오류로 차단한다.
검사 모델은 모든 의미 기준을 독립적으로 확인한다.
런타임은 배열·완료 플래그의 정확한 일치 여부만 검사 모델에 제공한다.
후보의 설명이나 참조 판정으로 이 정보를 만들지 않는다.

전송 기본값은 `structured`다. 첫 도구 인수의 중복 키와 스키마 오류를 즉시 차단한다.
CLI는 `--max-turns 1`을 사용한다. 추가 요청·재시도·출력 한도 복구를 수용하지 않는다.
외부 API의 생성 9필드와 검사 4필드 계약은 유지한다.
수동 QA 실행기와 opt-in Rust HTTP 어댑터가 같은 변환을 사용한다.
`text-json`은 명시적 대조 방식으로 유지한다.

생성·검사 역할은 적격성과 필수 중단 조건을 먼저 적용한다.
`smaller`는 최신 작업을 줄인다. 다른 작업 탐색은 replacement다.
예시 문구는 선택한 결과가 아니다. 유용한 결과의 선택 부담 감소도 기존 축소 기준에 포함한다.
공통 의미 계약과 참조 파일은 변경하지 않는다.

검사 호출 수는 한 번을 유지한다.
`smaller` 요청의 `need_info` 후보만 상태 분기를 좁힌다.
질문과 무관한 목표 초안·실행 행동·보류 유지의 상태 필드 지침을 제거한다.
허용 상태·질문 필요성·반복 실패·유용한 최소 작업의 중단 규칙은 그대로 복사한다.
다섯 기준의 전체 정의와 나머지 모든 계약 문단은 그대로 복사한다.
알려지지 않은 계약 문단이나 상태 규칙이 있으면 전체 계약으로 돌아간다.
다른 요청이나 후보 상태도 전체 계약을 사용한다.

검사 역할은 최신 작업의 적격성을 축소 탐색 전에 확인한다.
보류된 작업의 일부를 수행해도 그 작업을 재개한다. 질문에 작업을 언급하는 것은 실행이 아니다.
검사 모델은 다른 행동을 생성하거나 알려지지 않은 사실을 가정하지 않는다.
승인은 다섯 기준 번호를 모두 요구한다. 빈 증거나 불완전한 승인 번호는 차단한다.
차단 기록은 `invalid_check_fields`에 알려진 필드 이름만 남긴다.
모델 출력이나 판정을 고치지 않는다. 후보를 다시 생성하지 않는다.
모델·메시지·재시도·프로세스 정리와 실제 역할 시간을 기록한다.
