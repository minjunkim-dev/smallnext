# 첫 축소 거부의 사람 판정 자료 #121

확정 범위는 [#121](https://github.com/minjunkim-dev/smallnext/issues/121)을 따른다.
판정 기준은 [#47 확정 답](https://github.com/minjunkim-dev/smallnext/issues/47#issuecomment-6117399072)을 따른다.
[기존 사람 출력 검토 양식](subscription-launch-validation.md#사람-출력-검토-양식)을 아래에 구체화한다.
사람 판정 담당자는 `minjunkim-dev`다.

## 자료 연결과 확인

1. 기존 private 출시 묶음의 `manifest.json`이 있는 디렉터리를 확인한다.
2. `python3 scripts/human_review.py <private-launch-directory>`를 실행한다.
3. 공개 보고의 `ready`, `missing`, `mismatched`, `unreadable`을 확인한다.
4. `ready: true`일 때만 private 원문과 아래 빈 양식을 사람에게 전달한다.

명령은 기존 파일을 읽기 전용으로 연다. 기존 파일을 수정하거나 복사하지 않는다.
실제 모델·OAuth CLI·유료 API·네트워크 호출을 수행하지 않는다.
표준 출력에는 원문 대신 식별자·상대 경로·JSON pointer·SHA-256·확인 상태만 기록한다.
`ready: false`이면 종료 코드 1을 반환한다. 준비 완료를 차단한다.
누락·hash 불일치·읽을 수 없는 자료를 구분한다.
심볼릭 링크와 일반 파일이 아닌 자료는 읽지 않는다.

[기존 공개 실행 기록](fixtures/subscription-launch-results.json)의 manifest hash와 역할별 입력·출력 hash를 기준으로 확인한다.
`subscription-115-20261011`의 `fixed-ready-1` 첫 행동과 첫 축소를 연결한다.
각 요청 ID를 결과·요청·역할·완료 receipt에 연결한다.
첫 행동 입력은 manifest에서 읽는다. 직전 후보는 첫 행동 생성 결과에서 읽는다.
첫 축소 입력은 동결 실행기의 상태 전환으로 복원한다. 기존 공개 입력 hash로 확인한다.
복원한 입력을 저장하지 않는다. 보고에 원문을 넣지 않는다.
첫 축소 후보와 검사 근거는 `results/001.json`의 두 역할 출력에서 읽는다.
JSON 값 hash는 기존 `oauth_quality.encoded` 형식이다. 파일 바이트 hash와 구분한다.
현재 지침·계약·schema·참조 판정은 수정하지 않는다.

## 현재 준비 상태

2026-10-12에 기록된 #115 원문 경로에서 묶음을 찾지 못했다.
개발 worktree·Workspace·Codex 작업 디렉터리와 Git 보관 snapshot 18개를 확인했다.
원문 없는 [공개 준비 결과](fixtures/human-review-preparation.json)는 `missing: ["bundle"]`을 기록한다.
자료 준비는 **차단**이다. 사람 판정은 **미수행**이다. 품질 승인은 **미확인**이다.
원문이 복구되면 같은 manifest와 입력·출력 hash로 다시 확인한다.
공개 기록이나 재생성 결과로 원문 누락을 채우지 않는다.

## 빈 사람 판정 양식

이 양식을 private 작업 공간에서 작성한다. 원문 근거를 공개 Issue·커밋·로그에 복제하지 않는다.
준비 보고의 실행 판·manifest hash·사례 ID·두 요청 ID·출력 hash를 함께 참조한다.
에이전트는 아래 판정 칸을 작성하지 않는다.

| 실행과 표본 | 기록할 값 |
| --- | --- |
| 자료 준비 상태와 보고 위치 | 미확인 / |
| 실행 판·manifest hash | / |
| 사례 ID·첫 행동 요청 ID·첫 축소 요청 ID | / / |
| 첫 행동·첫 축소·검사 출력 hash | / / |
| 실제 검토자·검토 시각 | / |

각 판정은 `충족 / 불충족 / 미확인` 중 하나로 기록한다.
근거가 없거나 판정하지 않은 칸은 `미확인`으로 남긴다.

1. 자기 역할 제한의 보존과 목표에 필요한 결과를 각각 판단한다.
2. 결과가 후속 작업에 쓸 정보를 남기는지 판단한다. 유용한 역할 선택 표시를 일괄 금지하거나 일괄 수용하지 않는다.
3. 가용 5분과 첫 행동 추정 5분·첫 축소 추정 2분을 실제 수행과 구분한다.
4. 직전 후보의 필수 작업량과 비교한다. 시간 추정만으로 실제 장애 감소를 승인하지 않는다.
5. 문장 전체의 필수 의미·사실·남은 범위·완료 ID·완료 플래그를 함께 확인한다.

현재 지침은 직전 후보 비교와 실제 작업량 감소를 이미 요구한다.
지침 누락을 원인으로 단정하지 않는다. 과거 거부·실패 결과를 수용으로 덮어쓰지 않는다.
두 후속의 결과를 확인한 뒤 별도 수정 범위를 정한다.
