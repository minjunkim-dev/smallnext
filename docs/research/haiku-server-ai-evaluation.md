# Haiku 사용자용 서버 AI 준비

## 선택과 검증 경계

2026-10-09 사용자는 비용을 우선해 앱의 서버 AI를 Haiku 5.5로 선택했습니다.
[#47의 결정과 착수 기록](https://github.com/minjunkim-dev/smallnext/issues/47#issuecomment-6074604866)을 따릅니다.
생성과 별도 검사는 `claude-haiku-5-5 / medium`을 사용합니다.
기존 개발 전용 ChatGPT 구독 모델은 유지합니다.
서버 설정은 [SERVER_AI](../SERVER_AI.md)가 기준입니다.

모델 선택은 출시 품질 통과를 뜻하지 않습니다.
`user_server_ai` 기본값은 OFF입니다.
아래 평가에서는 의미 검사 오수용 1개를 발견했습니다.
실제 API 키·계정 접근·청구·Firebase 인증·운영 서버 배포는 검증하지 않았습니다.
#47을 완료로 닫지 않습니다.

## 변경 이유

2026-10-08의 제한 비교에서 Haiku xhigh는 반복해서 시작하지 못한 상황에 펜을 집으라는 행동을 생성했습니다.
별도 검사도 이를 수용했습니다. Haiku max의 첫 검사 호출은 120초에 중단했습니다.
이전 결과를 삭제하거나 새 결과로 소급 변경하지 않습니다.

서버 지침을 한 번 보완했습니다.
반복 제안에도 시작하지 못하고 원인이 미확인일 때는 첫 실제 걸림돌을 직접 묻게 했습니다.
더 작은 신체 동작을 이 질문의 대체로 수용하지 않게 했습니다.
알려진 제목 복사를 근거 확보로 수용하지 않게 했습니다.
공통 개발 프롬프트와 제품의 다섯 기준은 변경하지 않았습니다.

## 동결 평가

기존 합성 3사례의 입력과 고정 실패 후보를 그대로 사용했습니다.
각 사례에서 생성·생성 결과 검사·고정 실패 후보 검사를 한 번씩 수행했습니다.
최대 9 CLI 호출, 호출당 120초, 전체 360초로 실행 전에 고정했습니다.
자동 재시도·재생성·모델 대체는 없었습니다.
9회 모두 완료했습니다. 같은 구성을 계속 수정하는 평가를 추가하지 않았습니다.

기존 Claude 구독과 CLI 2.1.294를 사용했습니다.
완료 응답 9개의 실제 모델 ID는 모두 `claude-haiku-5-5`였습니다.
파일·셸·MCP 도구를 비활성화했습니다. 합성 입력만 전송했습니다.
이 실행은 일반 서버 API 인증·청구·지연 검증이 아닙니다.

| 합성 사례 | 생성과 검사 | 원문 기준 검토 |
| --- | --- | --- |
| 선택한 펜을 두 번 제안해도 시작하지 못함 | 첫 실제 걸림돌 질문. 검사 accept | 반복 막힘 정책과 일치합니다. |
| 과거 역할과 기록 위치를 모름 | 기록 위치를 메모하게 함. 위치가 떠오르지 않으면 `위치 없음`으로 완료. 검사 accept | 실패입니다. 모든 완료 대안이 유용해야 합니다. 이미 모르는 위치에 대해 `위치 없음`만 남기는 대안은 새 근거나 걸림돌 해소를 제공하지 않습니다. |
| 그림 하나 또는 단어 하나만 가능 | `어?` 한 단어만 쓰게 함. 검사 accept | 수량 제한과 남은 작업을 보존합니다. |

고정 실패 후보 3개는 모두 reject였습니다.
역할 근거 사례의 검사기는 유용성의 제한을 언급하면서도 accept를 반환했습니다.
나머지 사례의 성공으로 이 오수용을 상쇄하지 않습니다.
이 보조 원문 검토는 사용자의 실제 시작이나 전수 사람 품질 승인이 아닙니다.

생성+검사 CLI 시간은 사례 순서대로 13.188 / 25.436 / 15.381초입니다.
중앙값은 15.381초입니다. 표본은 각 사례 1회입니다.
출력 토큰 합계는 12,713입니다. 단일 호출 최대 출력은 2,541입니다.
API 요청의 thinking 포함 출력 제한 8,192를 CLI에서 강제한 것은 아닙니다.
CLI 보고 API 정가 환산 합계는 0.01118782 USD입니다. 실제 구독 청구액이나 출시 비용이 아닙니다.

## 기술 검사와 보관

Anthropic Messages의 헤더·단일 user message·구조화 출력·실제 모델·stop reason을 모의 HTTP로 검사합니다.
거부·불확실·출력 중단·도구 호출·구조 실패에서 후보를 반환하지 않습니다.
캐시 읽기와 쓰기를 전체 입력에 합산합니다. thinking은 출력 비용에 포함합니다.
모델 불일치와 캐시 포함 context 초과는 재시작 뒤에도 예산을 차단합니다.
미확인 사용량·취소에서는 예약을 임의로 환급하지 않습니다.
실제 PostgreSQL의 격리 schema에서 인증·동시 요청·예산·취소 경계를 검사합니다.

로컬 원문은 `.scratch/haiku-server-47-evaluation/`에 보관했습니다.
manifest에 입력·기대 실패 후보·프롬프트·schema·실행 상한을 고정했습니다.
manifest SHA-256은 `2a791c691710bed3faece75f5f19dcf931f83482b85fc27fab9c70411c2b3811`입니다.
이전 원문은 `.scratch/haiku-55-trial-v3/`와 `.scratch/haiku-55-trial-sonnet/`에 유지합니다.
보관 기한은 2026-11-08입니다. 자동 삭제는 없습니다. 사용자 원본 자료는 포함하지 않았습니다.

남은 출시 품질 문제는 위 오수용과 전체 고정 평가·사람 검토·실제 시작입니다.
실제 API 계정과 서버 인프라를 준비한 뒤 비용·지연·보관 조건도 별도로 검증해야 합니다.
