# 출시 검증 계획 #47

2026-10-11 계획 합의를 완료했다. 실제 유료 평가와 출시는 아직 완료하지 않았다.

2. [최종 검증 계획](https://github.com/minjunkim-dev/smallnext/issues/47#issuecomment-6103771425)은 추가 입력·경계·실행 상한·중단·측정·보관과 유료 실행 시점을 정의한다.

결정 상세는 위 Issue 댓글을 따른다. 이 문서에 같은 결정의 수치와 입력을 복제하지 않는다.

## 현재 준비와 유료 실행

개발 경로는 Claude Code 구독 OAuth와 `claude-haiku-5-5 / xhigh` 요청이다.
유료 API 검증은 사용자가 지정한 실제 별도 서버를 올리기 직전 단계에만 수행한다.
계획 합의나 이 문서의 병합으로 키 생성·유료 요청·서버 배포를 시작하지 않는다.
배포 후 유료 호출을 자동으로 추가하지 않는다.
피처 플래그 기본 OFF와 [#61 실기기 보류](https://github.com/minjunkim-dev/smallnext/issues/61#issuecomment-6051192063)를 유지한다.

## 개발 증거와 사용자용 API의 차이

[PR #103](https://github.com/minjunkim-dev/smallnext/pull/103)의 증거는 [결정 출력 검증](oauth-decision-validation.md)을 따른다.
과거 실패·참조 판정·미적용 시제품과 원래 결과를 보존한다.
개발용 합성 회귀·HTTP·iOS 시뮬레이터의 성공을 실제 API 청구·출시 품질·실기기 검증으로 확대하지 않는다.

PR #103의 개발 어댑터는 생성 5필드와 검사 3필드를 공개 9필드와 4필드로 변환한다.
`smaller`의 `need_info` 후보에는 질문용 검사 지침을 적용한다.
계획 합의 시점의 사용자용 API는 기존 생성·검사 schema를 직접 전송한다.
결정 출력 변환과 질문용 분기는 사용자용 API에 동일하게 적용되지 않았다.
이 차이는 `bb92b4601ab308675c4628fc04a1ed711124f2e2`의 준비 상태다. 후속 구현 전에 현재 소스를 다시 확인한다.

## 유료 호출 없는 다음 준비

1. 개발·사용자용 API의 지침·schema·출력 변환·최종 검사 차이를 확인한다. 공개 계약과 다섯 의미 기준을 유지하는 최소 변경을 준비한다.
2. [기존 고정 평가](server-ai-model-evaluation.md)와 확정 추가 입력·경계를 실행 JSON으로 만든다. 원래 fixtures와 참조를 변경하지 않는다.
3. 실행 하네스에 호출 수·시간·실패 중단과 순차 측정을 구현한다. 실제 요청 종류별 화면 응답·역할 시간·오류를 분리한다.
4. 오프라인 회귀와 개발 구독 검증의 구성을 고정한다. 이를 실제 API 청구·지연의 증거로 보고하지 않는다.
5. 키·계정·Firebase/IAM·UID·HTTPS·DB·삭제 스케줄러의 준비 상태를 확인한다. 실제 유료 호출은 지정한 직전 단계까지 미룬다.

이 준비 구현은 아직 완료하지 않았다. 구체 실행과 설정은 [사용자용 서버 AI](../SERVER_AI.md)를 따른다.

## 서버를 올리기 직전 확인

공식 모델 가용성·현재 가격·입출력 한도·전송·보관 조건을 실행 직전에 확인한다.
모델·effort·입력·prompt·schema·하네스·측정법·상한·보관을 동결한다.
첫 평가와 월 예산의 예약·정산·차단을 확인한다.
준비 조건을 통과하고 지정한 실행 단계에 도달해야 고정 유료 평가를 수행한다.
예산·시간·호출 수·예상 밖 오류 중 먼저 도달한 중단 조건을 적용한다.
부족한 결과를 자동 재호출하거나 출력·timeout·예산을 자동 증액하지 않는다.

실제 Firebase·HTTPS·DB·사용자용 API 전체 경로가 준비되지 않았다면 해당 근거는 미확인이다.
부분 API 평가 성공으로 배포 후 전체 경로까지 검증했다고 보고하지 않는다.
