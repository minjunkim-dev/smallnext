## 제품 범위와 평가 범위 정정

2026-10-04 사용자 정정: Smallnext는 사용자가 원하는 목표를 현재 실행할 행동으로 나누는 제품이다. 목표 종류를 이력서·포트폴리오로 제한하지 않는다. 제품의 핵심 흐름은 [제품 가설](../PRODUCT.md#핵심-흐름)을 참조한다.
[첫 버전의 대표 목표와 성공 기준](https://github.com/minjunkim-dev/smallnext/issues/3)은 초기 검증 사례다. 제품이 받을 수 있는 목표의 목록이나 경력 관리용 제품 사양이 아니다.
아래 216건은 이력서·포트폴리오라는 한 목표의 합성 사례에서 실행한 시험이다. 서로 다른 목표 216개를 시험한 것이 아니다. 이 결과로 범용 분할 품질을 판단하지 않는다.
고정 사례의 상태 손실·반복·막힘 처리 실패는 재현 자료로 유지한다. 이는 해당 입력·프롬프트 조합의 실패이며, 모델의 모든 목표에 대한 성능 순위가 아니다. 추가 범용 비교는 아래에서 구분한다. 제품 기본 모델의 최종 선택은 미완료다.
개인 경력 문장을 맥 메모 앱에 쓰도록 한 수행 요청은 철회했다. 제품 범위 설명과 평가 절차를 혼동하게 만든 요청이었다. 이를 사용자 시작 실패나 필수 응답 대기로 기록하지 않는다.

범용 점검에서 실패를 찾으면 해당 목표와 실패 원인을 고정 회귀 사례에 추가한다. [목표 분할 결과의 확정 품질 기준](https://github.com/minjunkim-dev/smallnext/issues/6#issuecomment-5968651172)의 기존 반복·경계 사례도 유지한다. 첫 검증 사례를 통과했다고 범용성을 주장하지 않는다.
범용 프롬프트로 수정한 뒤 `general-subscription-v1`이라는 새 판으로 실행했다. 과거 프롬프트의 시간·품질을 새 판의 결과로 사용하지 않는다. 기존 구독으로 42건을 추가했다. 일반 개발자 API 키 요청은 여전히 0건이다.
사용자의 실제 수행은 제품 흐름과 검토 방법을 구체화한 뒤 별도로 확인한다. 지금 개인 경력 작업을 수행할 필요는 없다. AI 보조 검토·사람의 출력 검토·사용자의 실제 시작 증거를 구분한다.

### 범용 반복·기존 회귀 재시험과 추천안

2026-10-05에 `repeated-goal-evaluation-v1`을 마쳤다. 후보별 117요청, 총 234요청이다. 범용 6목표의 첫 행동·재분할 2회를 각 3회 반복해 54요청, 경계 3종을 각 3회 반복해 9요청을 실행했다. 범용 세트는 후보별 63요청이다. 기존 대표 목표의 고정 회귀 54요청도 후보별로 실행했다.
이 판을 포함한 고정 평가 요청은 492건이다. 예비 시험 2건은 별도다. 요청 수를 서로 다른 목표 수나 실제 사용자의 수행 수로 확대하지 않는다.

남은 작업은 현재 막힘 유지·허용 수행량·최소 한계의 결함 보완, 수정 뒤 고정 세트 재평가, 사람의 필수 기준 검토, 실제 사용자 시작 확인, 일반 서버 API의 인증·비용·지연 측정이다. 현재 개인 경력 수행 과제나 필수 사용자 응답 대기는 없다. 실패가 있는 후보를 가격이나 CLI 시간으로 통과시키지 않는다.

## 합성 평가 입력 검토안

상태: 2026-10-04 사용자가 비교 진행을 승인했습니다. 예비 시험 뒤 같은 합성 상황으로 구독 CLI 반복 평가를 진행했습니다.
이 문서는 연구와 평가 기록입니다. 제품 기본 모델의 확정 답은 아닙니다.

기준은 [목표 분할 결과를 어떤 기준으로 통과시킬 것인가?](https://github.com/minjunkim-dev/smallnext/issues/6#issuecomment-5968651172)와 [첫 버전의 AI 연결 방식과 실패 시 동작은 무엇인가?](https://github.com/minjunkim-dev/smallnext/issues/10#issuecomment-5969227418)입니다.

### 공통 입력

아래 문장은 평가를 위한 합성 입력입니다. 실제 개인·회사 원문을 복사하지 않았습니다. 공개된 결정의 목표 구조와 경험 A의 종류만 사용합니다.

```text
목표: 준비 시작일부터 3주 안에 지원용 이력서 PDF 하나와 포트폴리오 PDF 하나,
대표 공개 저장소 1~2개와 기존 안내 페이지 하나를 정리한다.
완료 조건: 두 PDF의 경험·기간·역할이 서로 일치하고,
선택한 저장소의 설명 및 안내 페이지에서 자료를 확인할 수 있다.
이번 행동의 대상: 경험 A, iOS 빌드 환경 분리.
합성 원고: 경험 A의 제목만 있다. 실제 역할·수치·성과는 아직 확인하지 않았다.
사용할 수 있는 자료: 이 합성 원고와 앱에 남길 짧은 메모.
사용할 수 없는 자료: 원본 회사 문서, 비공개 저장소, 성과 측정 기록.
기본 제약: 링크를 읽었다고 가정하지 않는다. 없는 역할·성과·수치를 만들지 않는다.
현재 행동과 최종 목표의 완료를 구분한다.
```

이 입력은 실제 원고의 내용이나 경험 A의 역할을 확정하지 않습니다.
공급자에게 이름, 회사명, 연락처, 파일 경로, 저장소 주소와 문서 원문을 보내지 않습니다.

### 다섯 고정 상황

| 상황 | 공통 입력에 추가할 문장 | 기대 방향 |
| --- | --- | --- |
| 진행 가능 | 지금 짧은 메모를 쓸 수 있다. 역할을 설명할 문장은 아직 없다. | 역할 한 문장을 남기는 행동. 모르는 역할은 사용자가 적도록 한다. |
| 분량 부담 | 역할 한 문장을 쓰는 것이 부담된다. 먼저 표시 하나는 할 수 있다. | 역할 선택이나 표시 하나로 줄인다. 이미 안다고 가정하지 않는다. |
| 방법 모름 | 역할 문장을 어떻게 쓰는지 모르겠다. 빈칸 하나는 채울 수 있다. | 역할 표현의 예시 또는 틀을 제시한다. 예시를 실제 경력으로 단정하지 않는다. |
| 근거 부족 | 성과 근거가 없다. 지금 원본 기록에 접근할 수 없다. | 필요한 기록 종류 하나를 적는다. 접근 불가한 기록을 당장 열라고 하지 않는다. |
| 선택 어려움 | 어느 경험을 포함할지 모르겠다. 현재 맥락에 있는 후보는 경험 A 하나이다. | 경험 A의 적합성 또는 역할 하나를 표시한다. 새로운 경험을 만들지 않는다. |

두 번째 ‘더 작게’에서 이미 알려진 막힘을 다시 묻는지도 확인합니다.
고정 입력은 실행 중 임의로 바꾸지 않습니다. 수정하면 새 평가 판으로 기록합니다.

2. **이미 완료**: 역할 선택 표시와 완료 기록이 있습니다. 같은 역할 선택을 다시 시키면 실패입니다.
3. **작은 행동만 완료**: 역할 선택만 끝났습니다. 역할 문장·PDF·최종 목표는 미완료입니다.

## 구독 고정 평가: 실행 조건과 판정

사용자 승인 뒤 `subscription-v1`을 실행했다. 다섯 상황은 각 3회 반복했다. 각 흐름은 첫 행동과 재분할 2회로 구성했다. 경계 3종은 각 3회 실행했다. 후보별 54요청이다.

## 2026-10-05 현재 막힘 명시 실험

같은 구독 승인 범위에서 검증용 지침과 입력 구성을 보완했다. 제품 코드는 구현하지 않았다. 목표 종류를 제한하지 않았고, 개인 경력 작업이나 새 API 키를 요청하지 않았다.
검사할 가정은 ‘모델이 현재 막힘보다 남은 목록의 첫 항목을 우선한다’였다. 단독 원인으로 확정하지 않고, 지침 변경과 입력 위치 변경을 나누어 관찰했다.

### 사전 대조와 전수 실행

`focused-subscription-v1`은 공통 지침의 우선순위만 바꿨다. 대상 이름·현재 막힘·남은 목록을 구분했다. 기존 사실과 입력 구성을 유지했다. 성과 근거 부족·수행량 부담·여행 선택의 첫 행동을 각 3회 요청했다.
자동 검사 9건은 통과했다. 성과 근거 부족의 3회 모두 역할 작성으로 우회했다. 지침 문구만 강화하면 해결된다는 가정은 이 사전 시험에서 지지되지 않았다.

`focused-subscription-v3`은 같은 수정 지침과 사실을 유지했다. 기존 `context.situation`을 사용자 `request` 앞에 ‘지금 해결할 막힘’으로 다시 명시했다. 예상 정답과 특정 근거 종류는 입력에 추가하지 않았다. 동일 9건을 실행했다.
성과 근거 부족의 첫 행동 3회 모두 근거 처리로 바뀌었다. 1회는 확인할 기록 종류를 골랐다. 2회는 근거 없는 수치를 쓰지 않는 처리 정책을 정했다. 역할 작성 우회는 0회였다. 정책 선택을 필요한 기록 종류 선택과 같은 결과로 판정하지 않는다.

이 구성을 `focused-subscription-v4`로 고정하고 Sonnet 5.5의 전체 117요청을 실행했다. 범용 6목표와 3경계의 63건, 기존 합성 목표 5상황과 3경계의 54건이다. 각 흐름과 경계는 3회 반복했다. 첫 행동과 재분할 2회를 유지했다.
모델·low 추론·9필드 스키마·구독 인증·도구 차단은 이전과 같다. 독립 흐름 3개는 병렬로 실행했다. 각 흐름의 재분할은 앞 응답을 받은 뒤 순서대로 실행했다. Luna는 이번 판에서 재실행하지 않았다.
새 입력은 기존 사실·자료·남은 목록·완료 이력·고정 피드백을 유지한다. 달라진 부분은 공통 지침과 요청 앞의 현재 막힘 명시다. 재분할에 전달하는 앞 응답은 새 실행에서 생성되므로 이전 판과 다르다.
