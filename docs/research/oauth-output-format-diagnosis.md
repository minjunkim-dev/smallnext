# Issue #96: 단일 JSON 출력 형식 재현

Claude Code 구독 OAuth·`claude-haiku-5-5`·요청 effort `xhigh`를 유지한다.
실제 Rust 개발 HTTP 라우터와 수동 QA 어댑터를 사용했다.
운영 공급자, 앱 코드, 출력 스키마와 다섯 의미 검사 기준은 바꾸지 않았다.
모델 내부 effort를 독립 증명하지 않는다.

## 최초 기록과 재현

[PR #101의 43/47 기록](http-ios-checker-latency.md)은 그대로 보존했다.
최초 네 오류의 값은 저장되지 않았다. 당시 오류 필드는 소급 확정할 수 없다.
과거 오류가 전부 이번에 재현한 오류와 같았다고 주장하지 않는다.

네 대상 입력을 각 8회 실제 HTTP로 재생했다.
세 생성 사례는 실제 생성·독립 검사를 모두 호출했다.
`useful-minimum-unknown-invalid`는 동결 후보를 생성 단계에 넣었다.
이 사례의 생성은 stub이며 검사만 실제 OAuth다.
32개 HTTP 요청의 실제 모델 역할은 56회다.
`useful-minimum-unknown`의 새 검사에서 추가 필드를 관측했다.
HTTP는 23.240초 뒤 실패했다. `invalid_output`과 `additional/$`를 기록했다.
추가 필드의 이름과 값은 보관하지 않았다.

재현 명령: `python3 work/format96-probe/run.py`.
결과: `AssertionError: format validation failed`.

이어서 `useful-minimum-unknown-valid`의 고정 후보로 생성을 제거했다.
같은 Rust HTTP 라우터의 검사에서 Markdown 코드 블록을 관측했다.
`json_syntax`, 코드 블록 시작 여부와 assistant/result 텍스트 일치 여부를 기록했다.
텍스트 일치는 앞뒤 공백을 제외한 비교다. 원문은 저장하지 않았다.
이 오류에서 CLI가 모델 답을 다른 JSON으로 변환했다는 가설은 배제했다.
고정 검사 입력 해시는 `58f3843a785c14c88e76dbceb2a5d3d384f5fed6dda059b1261a509e28d43e8e`다.
프롬프트 해시는 `b2c180faf3caeaedde0c4f6ff61895079e5c3cd9de321c36841b5bad0b6c98e6`다.
스키마 해시는 `e5f80c4068234fcebb54847cf1b6dd3da5a677aac60b8647e64ce3a81c150297`다.
오류 검사 API는 8.955초다. 제공자 메시지는 하나다.

최소 재현 명령: `python3 work/format96-probe/minimise.py`.
수정 전 결과: `AssertionError: fixed check format failed`.
고정 후보 검사 11회 중 마지막 검사에서 코드 블록 오류가 발생했다.
별도 실제 생성 진단 4회도 수행했다. 고정 후보 검사로 계산하지 않는다.
임시 제어기의 주입 파일 경합 때문에 최소 재현의 1–4회는 실제 생성으로 실행됐다.
마지막 원래 요청과 첫 최소 재현은 한 번 겹쳤다.
원본 행을 덮어쓰지 않았다. 중복 기록은 입력 해시와 고유 역할 파일로 분리했다.
이 진단 실행을 성능 비교에 사용하지 않는다.

## 최소 수정과 회귀

공통 `text-json` 출력 지시에 중괄호 시작·종료와 정확한 최상위 필드 목록을 명시했다.
코드 블록·앞뒤 설명 금지와 JSON 문자열의 인용부호·줄바꿈 escaping도 명시했다.
코드 블록 금지는 객체 바깥에만 적용한다. 문자열 안의 backtick과 원문은 보존한다.
생성기와 검사기는 같은 실행 함수를 사용한다.
이는 출력 형식 지시만의 변경이다. 역할 계약·스키마·참조 판정은 유지했다.
추가 필드를 제거하거나 코드 블록을 벗겨서 수용하지 않는다.
자동 재시도, 검사 생략과 effort 변경은 없다.

`invalid_output` 오류 코드는 유지했다.
`output_error`는 고정된 종류와 신뢰된 스키마 경로만 추가한다.
종류는 `json_syntax`, `duplicate_key`, `text_type`, `type`, `required`,
`additional`, `enum`, `range`다.
추가 필드 오류의 경로는 부모 객체다. 알 수 없는 필드 이름과 값은 기록하지 않는다.
예외 메시지·추론 원문·자격증명은 저장하지 않는다.
기존 동결 실행은 실행기 바이트 해시가 달라 새 코드로 재생하지 않는다.
새 실행은 새 manifest에 동결한다.

출력 지시 회귀를 먼저 실패시켰다. 수정 후 통과했다.
구문·중복 키·누락·추가 필드·타입·중첩 배열·enum·숫자 범위 차단도 확인했다.
잘못된 값 `PRIVATE`와 알 수 없는 필드 이름은 기록에 남지 않았다.
어댑터는 분류 기록을 저장한 뒤 기존 Rust 실패 이벤트를 반환했다.
Python 140개, 하네스 28개, 어댑터 5개와 Rust 30개가 통과했다.
Rust DB 전용 11개는 로컬에서 제외했다.

스키마가 유효해도 Rust 보존 조건에서 실패할 수 있다.
`invalid_proposal_fields`는 실패한 고정 필드 이름만 기록한다.
기존 boolean 검사를 같은 함수로 표현했다. 검사 의미는 유지했다.
어댑터는 출력 값을 수정하지 않는다. Rust는 기존 보존 검사를 수행한다.
`remaining_work`와 완료 ID가 다른 출력의 원문 전달과 안전한 기록을 회귀 검사했다.

## 재검증

[수신 기록](fixtures/oauth-output-format-results.json)에 모든 재검증을 보존했다.
최초 43/47 및 이전 13/14·45/47 기록을 대체하지 않는다.
전체 품질의 경계는 PR #101과 같다. 고정 검사 33건은 직접 CLI다.
생성 14건은 실제 Rust HTTP에서 생성·검사를 모두 거친다.
이 구분을 모든 47건의 HTTP 검증으로 주장하지 않는다.

첫 출력 지시 초안의 고정 후보 HTTP 검사는 20/20 수용했다.
같은 후보 입력 해시를 사용했다. 형식 오류와 추가 메시지는 없었다.
이 초안은 이후 문자열 내부 원문을 보존하도록 표현을 명확히 했다.

| 실행 | 고정 CLI 검사 | 실제 HTTP 생성 | 참조 일치 | 형식 오류 |
| --- | --- | --- | --- | --- |
| 첫 형식 지시 초안 | 33/33 | 14/14 | 47/47 | 0 |
| 문자열 보존 표현 확정 | 33/33 | 13/14 | 46/47 | 0 |
| 보존 필드 계측 추가, 최종 코드 | 32/33 | 14/14 | 46/47 | 0 |

각 실행은 새 manifest에 동결했다. 병렬 수는 2다.
참조와 스키마는 PR #101과 같다. 모든 실행을 별도 보존했다.
최종 실행은 실제 역할 61회와 제공자 메시지 61회를 기록했다.
61개 출력은 모두 스키마에 맞았다. 추가 요청과 `max_tokens`는 0이다.
모든 역할의 모델 ID는 `claude-haiku-5-5`다. 남은 프로세스 그룹은 0이다.

두 번째 실행의 `original-report-smaller-repeat`는 `invalid_proposal`로 차단됐다.
생성 출력은 스키마에 맞았으나 Rust 보존 조건에서 실패했다.
검사기는 호출하지 않았다. 당시 잘못된 필드 값은 보관하지 않았다.
이후 보존 필드 계측을 넣은 단독 반복 4회는 모두 수용했다.
정확한 실패 필드는 아직 확인하지 못했다. 해결했다고 주장하지 않는다.

최종 실행의 `report-useful-title`은 참조 `accept`와 다르게 `reject`를 반환했다.
검사기는 기준 4를 지적했다. 출력 형식 오류는 아니다.
검사기는 선택 작업 감소를 인정하지 않았다.
이전 행동은 목차 첫 항목과 선택 예시를 제시했다. 후보는 쓸 제목 한 단어를 정했다.
동결 계약은 구체적인 단위를 정해서 선택 작업을 줄이는 경우를 허용한다.
참조 판정과 검사 기준을 바꾸지 않았다. 이 차이는 Issue #96에 남긴다.

원래 보고서 입력을 다른 모델 작업 없이 순서대로 4회 실행했다.
같은 생성 입력 해시는 `50ac8ea677b9f8c64fa526dd480b9666ac8801365d54912106bb0e642c91e728`다.
네 요청은 모두 수용했다. 생성 후보는 매번 달라질 수 있다.

| 반복 | 생성 CLI/API 초 | 검사 CLI/API 초 | HTTP 전체 초 | HTTP에서 두 CLI를 뺀 초 |
| --- | --- | --- | --- | --- |
| 0 | 21.276 / 20.253 | 23.330 / 22.397 | 44.996 | 0.390 |
| 1 | 16.965 / 15.945 | 38.648 / 37.644 | 55.768 | 0.155 |
| 2 | 35.613 / 34.503 | 29.202 / 28.085 | 64.985 | 0.170 |
| 3 | 19.691 / 18.695 | 27.893 / 26.877 | 47.738 | 0.154 |

API 시간은 공급자가 보고한 시간이다. 네트워크와 추론을 따로 측정하지 않는다.
마지막 열은 Rust 준비·프로세스 시작·어댑터·파싱·loopback 등의 합이다.
순수 전송 시간으로 해석하지 않는다. 화면 대기 시간도 포함하지 않는다.
기존 결과와 후보·시점이 다르다. 검사 지연 감소는 입증하지 못했다.
대부분의 대기는 생성·검사의 API 호출 안에 있다.
Issue #96을 닫지 않는다. 품질 47/47의 안정성도 입증하지 못했다.

진단용 임시 제어기와 shim은 `work/format96-debug/`에 보관했다.
위 재현 명령은 당시 실행 명령이다. 이동한 파일은 실행 가능한 배포 도구가 아니다.
재사용 경로는 커밋된 `oauth_bridge.py`와 Rust HTTP 진단 example이다.

## 검증 경계

개발 QA 어댑터를 넣은 서버의 PATH에서만 Claude를 사용한다.
피처 플래그 기본값은 모두 OFF다.
이번 수정은 실제 운영 공급자를 바꾸지 않는다.
실기기·VoiceOver·운영 활성화·배포는 검증하지 않는다.
새 iOS 화면 대기 시간은 측정하지 않는다. 이전 iOS 실측은 PR #101의 별도 근거다.
유한한 반복 성공으로 희귀 오류의 완전 제거를 보증하지 않는다.
제품 응답 SLA와 모델 일반 능력의 결함은 이번 결과로 확정하지 않는다.
