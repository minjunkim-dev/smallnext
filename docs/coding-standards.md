# 코딩 규칙

리뷰 에이전트가 읽는 기준 문서다. 구현 에이전트는 관련 Issue·도메인 문서와 [WORKFLOW](WORKFLOW.md)를 읽는다. 코딩 규칙 전체를 구현 컨텍스트에 일괄 주입하지 않는다.

기존 언어·계층·공통 interface를 유지한다. 새 dependency와 formatter는 필요한 경우에만 추가한다.
작은 interface 뒤에서 검증·오류·취소·자원 소유권을 함께 처리한다.
동일한 책임의 helper를 재사용한다. 범위 밖 리팩터와 저장소 전체 포맷은 하지 않는다.

## 동작 검사

Issue의 확정 완료 조건과 실제 변경을 비교한다. 피처 플래그 OFF 경로가 기존 동작을 보존하는지 확인한다.
저장 데이터·상태 전환·비동기 처리·오류 복구·접근성의 회귀를 확인한다.
사용자 화면에는 사용자에게 필요한 정보만 표시한다.
호출자가 사용하는 interface의 정상 경로와 실패 경로를 실행한다.
확인한 버그는 수정 전 실패하는 검사로 재현한다. 기존 검사가 재현하면 중복하지 않는다.
상수 재단언, 소스 문자열 순서, 성공만 반환하는 mock을 동작 검증으로 보고하지 않는다.
정적 검사는 action SHA·권한·문서 링크 등 정적 제약에 사용한다.
문서·설정 변경을 복제하는 테스트는 만들지 않는다.

## 신뢰 경계

입력은 env와 안전한 argv로 전달한다. 외부 입력을 shell 코드로 삽입하지 않는다.
인증·권한·입력 검증은 플래그와 관계없이 수행한다.
비밀정보·AI 원문·개인정보를 로그·검토 자료·artifact에 넣지 않는다.
Actions 기본 권한은 읽기다. 쓰기 권한·Secret은 필요한 job·단계로 제한한다.
제품·dependency 빌드는 배포 쓰기 권한과 production Secret을 받지 않는다.
외부 Action은 전체 SHA로 고정한다. 잠금 파일과 [도구 버전](../.ci/toolchains.json)을 유지한다.
인증·권한 검사, 민감정보 저장·로그·외부 AI 전송, 의존성과 CI 토큰의 변경을 검토한다.
비밀정보가 있는 작업에서는 PR 코드를 실행하지 않는다. `pull_request_target`은 기준 브랜치만 checkout한다. 봇의 자동 승인을 허용하지 않는다.

도메인은 [CONTEXT](../CONTEXT.md), 보안·서버 제약은 [SERVER_AI](SERVER_AI.md),
작업·플래그·병합은 [WORKFLOW](WORKFLOW.md), 저작권은 [COPYRIGHT](../COPYRIGHT.md)를 따른다.

## 영역별 회귀와 근거

- API는 OpenAPI·앱 호출자·기존 DB transaction·경합·롤백·삭제 범위를 함께 확인한다. 사용자용 서버 AI 기본 OFF와 인증 조회 실패 시 호출 금지를 유지한다. 예산 예약·정산·취소·시간 제한, 자동 재시도·재생성·모델 대체 금지와 미확인 사용량의 임의 환급 금지는 관련 SERVER_AI 계약을 따른다.
- iOS·Android는 목표·완료·보류·중단·삭제의 같은 도메인 의미, 저장·복구·취소·늦은 응답의 리비전을 확인한다. 접근성·앱 수명 주기·네트워크 오류·동의 경계를 유지하고 앱에 서버 비밀정보를 넣지 않는다. 기기 검증 보류를 단위 테스트·시뮬레이터·archive로 해제하지 않는다.
- 검증 스크립트의 오류·timeout·취소·하위 프로세스 회수·소유한 임시 파일 정리를 보존한다. 삭제·덮어쓰기·경로 탈출·큰 출력·부분 결과의 실패를 확인한다.
- GitHub 수집·집계·게시의 pagination·최신 attempt·head/base/merge SHA·publisher·최종 상태를 대조한다. Draft는 main source·같은 SHA의 CI를 확인하고 기존 Release·태그·asset을 덮어쓰지 않는다.
