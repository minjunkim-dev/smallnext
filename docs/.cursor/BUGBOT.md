# Smallnext 문서 리뷰 규칙

- 하나의 사실은 하나의 기준 문서에 기록한다. 원본 문서·ADR·과거 실행 근거를 삭제하거나 임의로 현재 사실로 바꾸지 않는다.
- 제품의 확정 결정은 사람이 확정한 Issue의 답을 따른다. 연구·검토안·봇 제안과 확정 사양을 구분한다. single-context의 도메인 용어를 유지한다.
- source·CI·mock·archive·실기기·운영·공개 배포의 증거를 구분한다. 미확인 범위·플래그 상태·검토 SHA·실행 ID를 숨기지 않는다.
- 절차는 WORKFLOW, 제품 가설은 PRODUCT, 도메인 용어는 CONTEXT가 기준이다. 변경한 문서의 링크·명령·사용 조건·보안 제약의 모순을 확인한다.
- Bugbot 규칙 파일은 짧은 검토 요약이다. 원문을 복제하거나 링크로 전체 문서 집합을 상시 수집하지 않는다. 필요한 계약은 관련 원본에서 확인한다.

기준 자료: `AGENTS.md`, `CONTEXT.md`, `docs/WORKFLOW.md`, `docs/DECISIONS.md`, `docs/coding-standards.md`, 관련 Issue의 확정 답.
