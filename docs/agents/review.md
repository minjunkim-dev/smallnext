# 로컬 독립 리뷰

로컬 구현 → 결정적인 검사 → 별도 Standards·Spec 리뷰 → 결함 수정·커밋 → 최종 전체 diff 리뷰·CI → 위험에 따른 승인 순서로 진행한다.
자동 AI 댓글과 Bugbot은 필수 CI와 독립 리뷰를 대신하지 않는다.

## 리뷰 입력과 소유권

1. 고정 base SHA와 최종 head SHA를 전달한다. 전체 `git diff BASE HEAD`와 변경 파일 목록을 전달한다.
2. Issue의 확정 완료 조건, 변경 범위, 실제 검사 명령·결과와 미확인 범위를 전달한다.
3. [코딩 규칙](../coding-standards.md), [WORKFLOW](../WORKFLOW.md), [CONTEXT](../../CONTEXT.md)와 관련 ADR을 전달한다.
4. Standards와 Spec을 별도 컨텍스트에서 실행한다. 권한·trust·승인·Secret·외부 명령·경로·삭제·dependency·workflow 권한 변경은 별도 보안 리뷰도 실행한다.
5. 직접 수정할 파일 소유권을 나눈다. 다른 작업자의 변경을 보존한다. 확실한 결함은 범위 안에서 수정하고 커밋한다.

Standards는 규칙·검사 품질·단순성·오류 처리·자원 소유권을 확인한다.
Spec은 Issue 완료 조건·호출자 동작·회귀·OFF/ON·접근성을 확인한다.
불확실하거나 범위 밖인 지적은 파일·위치·발생 조건·영향·근거와 함께 보고한다.
P0/P1은 병합 전에 해결한다. P2는 수정하거나 후속 Issue와 이유를 기록한다.
결함 수정 후 최종 head의 전체 diff를 다시 확인한다. 같은 head·base의 통과 검사는 재사용한다.
실제 실행하지 않은 독립 리뷰를 완료로 표시하지 않는다.
같은 모델이면 같은 모델의 별도 컨텍스트라고 기록한다. 소스 리뷰를 기기·운영 검증으로 보고하지 않는다.

## Bugbot 보조 리뷰

필요한 PR에서만 수동으로 실행한다. 지적을 실제 결함·오탐·판단 보류로 나눈다.
확실한 결함만 수정한다. 요청 ID·head·규칙 포함 여부·관측 사용량을 기록한다.
neutral check와 지적 0건은 결함 부재의 증거가 아니다.
반복된 실제 결함은 재현 검사·자동 체크·코딩 규칙으로 옮긴다.
자료를 찾지 못한 문제는 AGENTS의 경로 안내를 수정한다. 가상 문제를 위한 자동화를 추가하지 않는다.
